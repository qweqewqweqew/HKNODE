## 已知偏差

1. 共享内存垫片：调用点是 `shared_memory_object::remove`、`create_only`、`open_only`、`mapped_region`。未找到 Boost 头文件时，这些类型由 `include/shm/interprocess.hpp` 用 Windows 文件映射实现，文件放在临时目录 `industrial_camera_shm`。安装 Boost 后应切换到官方 Boost.Interprocess，当前构建没有这层切换。
2. `workpiece_id` 只放在 `ShmImageFrame`。64 字节槽头没有字符串字段，槽头保存 `trigger_seq_id`。
3. `trigger_queue_depth` 是拓扑里的可选键，默认 1。
4. 一令一参覆盖是粘性的。
5. `[STAT]` 在架构原有字段之后增加了「孤儿迟到帧」。
6. 曝光和增益影子缓存用 `atomic<uint32_t>` 保存 float 位型。
7. ROS 通知的 QoS 为 reliable、深度 10。原文未写 QoS。
8. 无真机。模拟设备只存在于 `tests/test_core.cpp`。运行库已随节点安装，但还没有用真实相机做过取流。

## 运维

- 日志目录：拓扑 `log_dir`，文件 `camera_node.log`，超过约 8MB 滚动为 `.1`
- `[STAT]` 字段：触发成功、闭环调参与防抖跳过、当前曝光增益和版本、平均共享内存写耗时、活跃槽位峰值
- 丢帧：SDK 网口丢包看网线和巨型帧；硬件帧断层看触发频率；写满丢帧看下游耗时和槽数；超时强占看卡死进程和 `shm_lock_timeout_ms`；触发超时看曝光加读出时间；断线重连单独计数，不计入硬件帧断层

## 安全与权限

- 共享内存名不含反斜杠
- 样例里的 `shm_permissions: "0666"` 在 Windows 上不表示 Unix 权限。映射文件位于当前用户临时目录
- GigE 建议网卡巨型帧 9014，并调大 `GevSCPSPacketSize`
